**Windows 高速下载器 · C# / WPF 重构版**

这一版集中在三件事上：**不再被 GitHub API 限流卡住**、**失败不再静默**、
**慢分片会真正换线**。同时修掉了几处会直接误导用户的数据与显示问题。

## 解析：不再依赖 GitHub API

### 问题

未配 Token 时，GitHub API 每 IP 每小时只有 **60 次**。撞上限后请求 403，
还会重试一轮 —— 实测一次解析要 **8.5 秒**才失败。用户看到的就是「遮罩一直转圈」。

### 改法

实测发现：**只有 `api.github.com` 消耗配额，下载走 CDN 完全不消耗**。
于是把所有「查元数据」的调用换成等效的页面路径：

| 原来（消耗配额） | 改成（零消耗） |
|---|---|
| API 查最新 Release | `expanded_assets` 页面 + 顺 302 取 tag |
| API 查默认分支 | 直接用 `HEAD`（它是合法 git ref） |
| API 查 Gist 归档 | 从页面 HTML 正则取 `archive/<sha>.zip` |

| 场景 | 修复前 | 修复后 |
|---|---|---|
| Release 链接（未配 Token） | 8.5s **失败** | **2.4s**，28 个资产全带大小 |
| 指定 tag | — | 0.5s |
| 任意仓库 Release | — | 1~2s |

**现在解析和下载都不碰 API**，60 次/小时的限制不再影响正常使用。
Token 的定位也变了：不再是「提额的必需品」，只在访问**私有仓库/私有 Gist** 时才需要。

### 附带：配额可见

设置页新增「API 配额」一行。数据取自响应头 `X-RateLimit-*`，**不额外发请求**
（否则查配额本身就要花一次）。剩余 ≤10 次时标红。

## 失败不再静默

排查发现：**64 处错误只写日志、0 处提示**。用户不打开日志面板就完全不知道出了事。

按场景分两级：

| 场景 | 形式 | 为什么 |
|---|---|---|
| 解析失败 / 超时 / 异常 | **模态弹窗**（「知道了」） | 用户的主动操作，失败了什么都没有，必须强制确认 |
| 下载失败 / 磁力失败 | **右下角浮层** | 批量下载可能同时失败多个，连弹模态框会逼疯用户 |

两类都同时写日志：弹窗给人话，日志留全量细节。

**技术错误翻译成人话**：

| 原始错误 | 给用户看的 |
|---|---|
| HTTP 403 | 网盘直链可能已过期，请重新解析 |
| 所有线路均不可用 | 检查网络，或在设置里换线路 |
| IOException | 检查磁盘剩余空间和写权限 |

**解析增加 45 秒整体超时**。原来每步都有超时（8~100 秒），但组合起来可能极久，
遮罩会永远挂着 —— 比明确报错糟得多。

## 下载：慢分片会真正换线

### 修的是一个真 bug

慢连接抢占原本只是「断开重连」：

```csharp
// 抢占 → attempt 归零 → 又选中同一条慢线
var (name, baseUrl) = urls[attempt % urls.Count];
```

于是白付一次 TCP+TLS 握手，速度分毫不动。

### 现在的行为

分片被抢占时，把它当时用的线路加入**该分片的黑名单**，重连时跳过：

```
拉黑 A     → 选 B / C / B      （跳过 A）
拉黑 A+B   → 全部选 C
全拉黑     → 退回原顺序         （不会卡死）
```

实测依据：`cdn.gh-proxy.org` 的 8 条连接里有 5 条只有 20~44 KB/s，
而 `gh-proxy.com` 同期是 190~250 KB/s —— 这类连接**不会失败**，只会一直慢，
不换线就永远慢着。

### 太慢的线路不参与择优

探测只发 `Range: bytes=0-0`（1 个字节），拿到 206 就判「可用」。
但存在这种线路：1 字节能秒回、下 512KB 要 32 秒。它「可用」却会拖死全部 worker。

现在速度低于 **48 KB/s** 的线路排到最后（日志会写明「太慢，不参与择优」）。
**若所有线路都慢则不干预** —— 压了也没意义。

### 分片算法修复

```
线程  2 → 4 块 → 2 线程     ✓
线程  4 → 1 块 → 1 线程     ✗ 线程越多越慢
线程  8 → 1 块 → 1 线程     ✗
```

根因：块大小算出小于 256KB 时，代码直接「整块装下」，彻底放弃并行。
2MB 文件按 8 线程算得 128KB < 256KB → 1 块 → 1 线程。

修复后按「能切几块切几块」处理。实测 8 线程下载 2MB：
**28774ms → 4105ms，快 7 倍**。

## 数据与显示修正

### 重命名后重启不再还原

`Upsert` 的 UPDATE 分支**漏了 `file_name` 和 `save_dir`** —— 参数绑了但 SQL 没用。
所以「同名自动改名」和「用户重命名」的结果从来没写进库：磁盘上是 `X (1).ext`，
库里还是 `X.ext`。

### 同名任务显示保存目录

文件名相同不代表同一个文件。下到不同目录的两个 `rg.zip` 在列表里完全一样，
只能点「定位」跳到别处才发现。

现在**只在真有重名时**，时间行末尾追加「保存到 <目录>」—— 不重名就不显示，
否则每条都挂一长串路径，界面会很吵。

### 下载记录显示时间

卡片底部新增一行：`今天 14:32 开始 · 用时 1 分 23 秒 · 今天 14:33 完成`

耗时是**累计真正传输的时间**，不含排队和暂停 —— 用时间戳相减会把等待也算进去。

## 界面细节

- **弹窗按钮被截断**：`SizeToContent.Manual` + 在窗口未进视觉树时 `Measure`，
  量出的高度接近 0，落到兜底 200px，而实际要 242px。改回 `SizeToContent.Height`。
- **去掉弹窗的「取消」按钮**：右上角 ✕ 就是取消，重复且挤占宽度。
- **主操作按钮不能靠位置猜**：选项顺序语义不一致（「覆盖/重命名」安全的是后者，
  「仅删记录/连文件一起删」危险的是后者），改为调用方显式指定。
- **输入框占位提示与光标对齐**：`PART_ContentHost` 的 `Padding` 被加了两次
  （模板 `Margin` + `ScrollViewer` 自身继承），实测文本起点 29px 而非 14px。
- **解析遮罩**：解析时覆盖半透明层 + 转圈 + 实时阶段文案
  （正在探测仓库 → 已取到 N 个资产 → 正在测速各条线路），不再让人怀疑卡死。
- **删除类操作全部加确认**：下载记录（可选连文件一起删）、收藏、单条历史、清空历史。
- **同名文件冲突询问**：覆盖原文件 / 重命名文件（覆盖需二次确认）。
- **解析卡片「粘贴」改为「清空」**：输入框本就能 Ctrl+V，清空才是刚需。
