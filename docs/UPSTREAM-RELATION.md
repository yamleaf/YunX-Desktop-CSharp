## 3. 改造清单：为什么动它

### 3.1 上游的结构性问题（本项目重做的部分）

| 问题 | 上游表现 | 本项目做法 |
|---|---|---|
| 单镜像硬编码 | `MIRROR_PREFIX = "https://cdn.gh-proxy.org/"` 固定一个前缀，镜像挂了/变慢就整体受影响 | 多线路池 + 测速择优 + 失败冷却；探测与分片共用同一套线路顺序 |
| 分片大小先定块数后算 | 先算 `chunk` 再 `ceil` 块数，尾块会退化成碎片（上游实测日志出现过 **15 字节**的块） | 反过来：先定目标块数（线程×2），用 `ceil` 反算块大小；并加尾部收缩，剩余不足 N 块时压小块让所有连接并行冲完 |
| 无慢连接识别 | worker 绑定一条连接后，慢就一路慢到底 | 看门狗周期采样，按**在飞分片速度中位数 × 0.4** 判定掉队；要求**连续两次采样**都偏慢才抢占（单次抖动不抢） |
| 断点续传只比总大小 | 内容变了但大小相同 → 拼出损坏文件 | ETag / Last-Modified 通过 `If-Range` 校验；区间用 `IntervalSet` 精确记录，落盘为元数据 |

### 3.2 本项目新增的能力

| 能力 | 为什么加 |
|---|---|
| **任务持久化** | 上游重启即丢任务列表。本项目用 SQLite 存未完成任务，并保存请求头 / 网盘上下文 / 断点路径 / 下载目录快照，重启后可续传 |
| **分片首尾哨兵校验** | 能抓住 `pwrite` 偏移写错、区间重叠、数据未落盘 —— 这些是"文件长度对但内容错"的静默损坏 |
| **单流续传** | 上游单流路径不做预分配也不写元数据，中断即整包重下。GitHub 仓库 zip（codeload 不支持 Range）正是最常用场景 |
| **磁力下载** | 复用上游"Gopeed 子进程"的路线（BT 协议自己实现不现实），但内核改为**自动下载安装 + 镜像优先**，并对非法 info hash 做前置拦截（否则 Go 侧会 panic 导致引擎整个退出） |
| **README 渲染** | 自研轻量 GFM 解析（标题/代码/列表/引用/表格/行内格式），不引 Markdown 库以控制单文件体积 |
| **凭证加密** | AES-256-GCM + 信封加密；主密钥按三档保护（明文 / 机器绑定 / DPAPI 用户绑定） |

### 3.3 有意移除的功能

| 功能 | 移除理由 |
|---|---|
| **自动更新** | 上游的更新检测比对的是**上游自己**的 Release tag。本版版本号从 `1.0.0` 重新起算，比出来必然"有新版本"，而那些包是 Kotlin 版 —— 引导用户装错程序，比没有该功能更有害。真要做需要：自建 Release 仓库 + tag 与程序集版本同源 + 匹配单文件分发的更新流程 |

### 3.4 保留不动的机制

这些上游做得对，本项目沿用其思路：

- **慢连接抢占**这个机制本身（只重做了判定阈值）
- **Range 降级容忍**：服务器偶尔忽略 Range 时不立刻失败，容忍若干次后整体降级为单流
- **API 缓存 + 401 自愈**：Token 失效自动清空并转匿名
- **信封加密**：换保护档只重新包裹主密钥，不动已加密数据

## 4. 技术栈对照

| 维度 | 上游 | 本项目 | 迁移代价 |
|---|---|---|---|
| 语言/运行时 | Kotlin / JVM | C# / .NET 8 | 需目标机有 .NET 运行时；本项目用**单文件自包含**规避 |
| UI | Compose Desktop（Skia） | WPF（DirectX） | 控件体系完全不同，界面全部重写 |
| 打包 | jpackage / gradle | `dotnet publish` 单文件 71 MB | 无需安装器 |
| 内嵌浏览器 | JCEF | WebView2（系统自带 Edge 内核） | 体积小得多，但依赖 WebView2 运行时 |
| 数据存储 | Room（SQLite） | Microsoft.Data.Sqlite | 需手写迁移 |
| HTTP | OkHttp | HttpClient + SocketsHttpHandler | 连接池 / 代理 / DoH 逻辑需自己搭 |

## 5. 已知差距（相对上游）

| 项 | 状态 |
|---|---|

| 渲染后端可选 | WPF 无此概念 |
| 10 个网盘的真实链路验证 | 逻辑层有断言覆盖，**网络层无真实账号验证** —— 只能确认"能构造出正确请求"，不能确认"能拿到直链" |
