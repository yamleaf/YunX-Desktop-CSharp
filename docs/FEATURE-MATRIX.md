## 未移植项说明

### 1. 中文口令解析

原项目逻辑：把口令原文发往**第三方服务**（迅雷口令接口 + 星海口令服务）换回 `pwdId`，再合成标准分享链接。

未移植的原因：依赖外部服务的私有接口，且会把口令原文发往第三方。这属于功能而非技术难点，接入位置已留好（`ICloudDrive.ResolveTextAsync`），接上即可用。

### 2. 迅雷账号密码 + 短信验证

原项目由系统浏览器承载验证页，再回调取 Cookie。C# 版已具备 WebView2 内嵌浏览器，技术上可行，但**没有真实账号无法验证**，移植无法验证的登录流程风险高于收益。

### 3. 渲染后端可选

`YUNXPC_RENDER_API=SOFTWARE|DIRECT3D|OPENGL` 是 Compose/Skia 的概念，WPF 走 DirectX 合成，无对应开关。

### 4. 网盘移植状态

原项目 10 个网盘共 8256 行。本版建立了统一插件架构（`ICloudDrive`）并移植了 6 个主流程，**代码行数从 8256 → 约 2200**（UC 因继承夸克基类只用了 80 行）。

| 平台 | 实现 | 登录方式 | 验证状态 |
|---|---|---|---|
| 123 云盘 | `Pan123Drive`（签名算法 + 免转存取链） | 账号密码 → JWT | 链接解析/签名格式已测；**接口调用未验证**（无账号） |
| 夸克 | `QuarkDrive`（免转存 + 分享凭证换直链） | 浏览器导入 / Cookie | 链接解析已测；**接口未验证** |
| UC | `UCDrive`（继承夸克，仅覆盖域名与 pr 参数） | 浏览器导入 / Cookie | 链接解析已测 |
| 139 | `C139Drive`（AES-CBC + mcloud-sign） | 浏览器导入 / Cookie | 链接解析/签名格式已测 |
| 百度 | `BaiduDrive`（验证→列举→**转存**→取链→清理） | 浏览器导入 / Cookie | 链接解析已测 |
| 迅雷 | `XunleiDrive`（10 层 md5 captcha_sign、中文口令） | 账号密码 + 短信 / Cookie | 链接解析/签名格式已测 |
| **蓝奏云** | `LanzouDrive`（acw_sc__v2 人机校验、down_ip、跨域 ajax） | 匿名可解析 / 账号密码 | 域名族识别、acw 算法已测 |

| **光鸭云盘** | `GuangYaDrive`（dt/traceparent/did 设备头、游标分页） | 匿名可下载 | 链接解析已测 |
| **星海（口令）** | `StarSeaCommandResolver`（非网盘：口令 → pwdId → 夸克/UC 链接） | 仅需内置 Key | 口令判定、链接合成已测 |

**关于星海**：它不是网盘，没有分享链接和取直接口，只做「中文口令 → pwdId」这一步，随后完全复用夸克/UC 链路。因此它挂在 `SourceResolver` 的口令兜底分支上（迅雷口令优先），而不是注册成 `ICloudDrive`。

**蓝奏的三个坑**（都已实现）：
1. `acw_sc__v2` 人机校验：40 位 hex 的 `arg1` 按位置表重排 + 与固定掩码异或，算出 Cookie 后重放。纯字符串变换，不需要 JS 引擎。
2. 下载节点必须带 `down_ip=1` Cookie，否则拒绝下发直链。
3. 新版下载接口跨域（`apifile.woozooo.com`），地址在页面 `domain1`/`domain2` JS 变量里。

**115 的三个坑**（都已实现）：
1. `user_id` 必须是**分享者** UID（snap 响应的 `userinfo.user_id`），不是自己的。
2. 取链要用 115 客户端 UA，浏览器 UA 会被判「版本过低」拒发直链（50029）。
3. CDN 同时校验登录 Cookie 与取链下发的 900 秒 CDN Cookie，缺任一 → 403。且该 Cookie path 绑定到对象路径，不能跨文件复用。

**必须说清楚的一点**：上述接口的**请求/响应字段全部依据原项目的抓包实证**，但本版**没有真实网盘账号**，所以「登录后能否真的取到直链」这一步**未经端到端验证**。签名算法、链接解析、错误码映射等纯逻辑部分有断言覆盖（见 `YunX.Smoke`），网络层则需要你用自己的账号实测。

**本轮已补齐蓝奏、115、光鸭、星海**，10 个平台全部到位。网盘代码量约 3900 行（原项目 8256 行）。

### 5. 通知中心改造说明

原项目用 WinRT toast 做通知中心进度，为此需要注册 AppUserModelID + 开始菜单快捷方式，还做了「送达自检 + 快捷方式兜底」——因为 WinRT toast 在未正确注册时会**静默丢失**。

本版改用 **任务栏进度条（`ITaskbarList3`）+ 托盘气泡**：
- 不写用户开始菜单、不需要 appx 身份、不会静默丢失；
- 进度直接显示在任务栏按钮上，可见性反而更好；
- 多任务聚合同样保留。

这是**有意的技术选型差异**，不是遗漏。

### 7.1 换电脑后登录态失效 —— 这是设计，不是缺陷

默认凭证保护档是「普通（绑定本机）」：主密钥用**机器标识**派生的 KEK 包裹
（PBKDF2 21 万轮）。把数据目录拷到另一台机器，`credential.key` 解不开 —— 这是**刻意的**。

**为什么不做成可随意搬迁**：网盘 Cookie / GitHub Token 等价于账号控制权。
若数据目录拷走就能在别的机器继续用，那"拿到一份备份"就等于"接管所有账号"。
绑定本机让这条攻击路径失效：攻击者还得控制那台机器本身。

**需要跨设备时的正路**是 `.yunx` 认证备份（口令派生密钥，与机器无关）：

1. 在**原机器**上「导出备份」（此时主密钥还能解开本机凭证）
2. 在新机器「导入备份」，输入同一口令
3. 新机器用自己的主密钥重新加密落库

**不需要**把保护档改成「宽松」—— 那会把主密钥明文放进数据目录，
等于放弃上面那条防线。

### 7.2 单文件分发的边界

| 项 | 说明 |
|---|---|
| exe 可放任意位置 | 单文件自包含（71 MB，无需 .NET 运行时）；无任何 exe 相对路径依赖 |
| 数据位置 | 固定在 `%APPDATA%\YunX-Desktop-CS\`，**不随 exe 移动** |
| 磁力内核 | 需单独下载（约 38 MB），存于同一数据目录，换机器需重装 |
| WebView2 | 内嵌登录需要。Win10/11 一般随 Edge 自带；缺失时仍有「导入浏览器 Cookie」「手动粘贴」两条路 |

当前**不是**便携模式（数据不在 exe 旁边）。真要做 U 盘即插即用，需要新增开关把
数据目录改为 exe 同目录，并强制 Portable 档 —— 但那样密钥会跟着盘走，需自行权衡。
